# Gestalt Standalone & Plugin Integration Specification

## 1. Overview
This document outlines the architectural specification for operating the Gestalt orchestrator in two primary modes:
1. **Standalone Mode:** As an independent multi-agent meta-orchestrator CLI.
2. **Plugin Mode:** As a sub-agent plugin within the Xavier cognitive architecture.

## 2. Standalone Mode Architecture

In Standalone Mode, Gestalt operates as the primary orchestrator, managing agent lifecycles, virtual file system isolation, and event bus state.

### 2.1 Core Components
- **CLI Entrypoint (`gestalt_cli`):** Handles user inputs, `run` executions, and `bus serve` processes.
- **Event Bus (`gestalt-state`):** SQLite-backed persistence for `run_started`, `checkpoint`, and `run_finished` events.
- **Worktree Sandboxing (`gestalt-router`):** Isolates agent tasks in git worktrees, applying `git merge-tree` integration.

### 2.2 Execution Flow
1. **Task Definition:** User provides a goal via `gestalt run --task "..."`.
2. **Environment Setup:** `gestalt-router` initializes isolated git worktrees.
3. **Execution Loop:** Sub-agents execute concurrently. State updates are pushed to `/api/event`.
4. **Integration:** Successful branches are merged. Failures are reported.

## 3. Plugin Mode (Xavier Integration)

In Plugin Mode, Gestalt acts as an execution engine triggered by Xavier's thinking loops or explicit MCP tool calls.

### 3.1 Architecture Integration
- **Command Proxy:** Gestalt delegates heavy context outputs to Xavier RTK Proxy (`xavier exec` or `xavier_run_command`) to optimize token usage.
- **MCP Tool Bridge:** Gestalt exposes tools (e.g., `memory_search`, `agent_status`) via `gestalt mcp serve`, allowing Xavier to interact with Gestalt's internal state.
- **Memory Archival:** Run results and decision logs are explicitly archived to Xavier via POST `/v1/memories` under paths like `gestalt/decision/<uuid>` and `gestalt/cycle/<timestamp>`.

### 3.2 Telemetry & Context
Gestalt automatically extracts `XAVIER_CONTEXT` from environment variables, appending execution summaries for downstream agent context propagation. Telemetry markers (`[xavier-proxy]`) trace token savings generated by RTK-filtered commands.

## 4. Fallback Mechanisms
Gestalt maintains a strict fail-open policy when Xavier is unreachable:
- Execution falls back to direct `sh -c "<cmd>"`.
- Context retrieval returns empty strings.
- Telemetry marks `tokens_saved_est=0`.
